## Test objective

Prove that each participant can answer: **What is mine, what is due, what am I waiting for, and who gets it next?** Everyone should refer to the same vacancy record throughout.

Use one workflow type and one fictional case. First rehearse the process together using the current owner review; then repeat the case across separate staff accounts after shared storage and access are implemented.

## Round 1 — 45-minute facilitated rehearsal, available now

Craig opens `/admin/habu-paper/workflows` in his own account and shares the screen. Participants direct their own steps while Craig operates the role preview. Use a fresh **Start vacancy**, not a precompleted example. Keep the page open throughout; refreshing resets it.

| Step | Person directing | Action | Required observation |
| --- | --- | --- | --- |
| 1 | Front Desk | Enter the fictional header. Attempt notice handoff with a task unchecked, then finish the notice tasks and hand off. | Incomplete work is blocked. PM owner preparation and Front Desk keys become Ready independently; inspection remains Coming Soon. |
| 2 | PM | Leave owner name empty and try to hand off; then enter owner name/date, rent, term and availability. Mark the landscaper task N/A with a reason. | Missing required fields block handoff; N/A needs a reason. Completion releases advertising without requiring keys. |
| 3 | Front Desk | Complete advertising. Put key receipt in Waiting with reason and follow-up; then resume. | Waiting work remains owned and visible. Advertising can finish while keys are still outstanding. |
| 4 | Front Desk | Apply the fixture's key-return schedule, complete key fields and checks, and hand off. | Date preview shows Day 1/8/10. Applying dates alone does not finish key receipt. Handoff releases PM inspection and Accounting together. |
| 5 | PM | Inspect, add the two sample work orders and hand off inspection. | Maintenance becomes Ready. The full sheet preserves the values entered by Front Desk and PM. |
| 6 | Accounting | Set its separate due date and mark Waiting for the sample invoice, with follow-up. | Accounting remains visible in Waiting; its deadline is independent of the property-ready schedule. |
| 7 | Maintenance | Complete only one work order and try handoff; then complete the second and hand off. | Unfinished work blocks handoff. Completing both releases PM verification. |
| 8 | PM, then Accounting | Verify readiness while Accounting is waiting. Then resume and complete simulated accounting. | Property reads ready while accounting remains open. Eventually all eight assignments are complete, with handoff history. |

At each handoff ask the receiving person to explain their next action, due date and dependency before coaching them. Record confusing wording, missing fields and routing disagreements. Review the shared master sheet and selected-section view together.

At the end, capture results outside the demo before closing it. A successful screen-share rehearsal validates the proposed process; it does not validate cross-user handoff.

## Minimum work before passing it between separate staff logins

1. Save a versioned case, field values, assignments, work orders and action history in shared storage. Reload and another device must show the same record.
2. Map pilot roles to actual authenticated staff and backups. Restrict the pilot to named participants; role preview must not grant authority in the shared pilot.
3. Enforce edit, completion, schedule and reassignment permissions on the server. Decide who can change shared header fields and deadlines.
4. Make a handoff one atomic operation: save completion, record the authenticated actor and server time, and release eligible downstream assignments together. Retries must not duplicate it.
5. Detect conflicting edits rather than silently overwrite another person's work. Record field/date changes and reassignments, not just completion events.
6. Add a stable case link, with an assignment link or clear selected section, so recipients open the same record in their own account.
7. Define corrections after completion: who can reopen a step, what happens to dependent work, and how the original action remains visible. The latest review lacks a correction control for a checked task.
8. Connect only the documents needed for this case, using a selected template version. Editing a blank library draft currently does not edit a running case or supply an attached document.

First shared implementation should support this single vacancy path. The existing notice, owner, keys, inspection, maintenance, verification, advertising and accounting sequence is the scope; new workflow types can follow after this test passes.

## Acceptance checks and evidence

| Area | Test type | Pass condition |
| --- | --- | --- |
| Routing and required fields | Existing unit tests + eight-step rehearsal | All eight assignments route correctly; every scripted blocked attempt stays blocked |
| Dates and waiting | Unit tests + UI review | Day 0/1/8/10 are correct; accounting stays independent; Waiting retains reason, owner and follow-up |
| Forms | Existing export tests + source review | Required vacancy fields agree with the chosen master; export reflects current draft values; users understand template versus case |
| Shared state | API/database integration + separate browsers | Zero lost changes after reload or device change; recipients see the same case and new assignment |
| Permissions | Direct API and page tests | Unassigned and non-pilot accounts cannot mutate the case; client role changes cannot impersonate staff |
| Retry and concurrency | Database integration | Repeated handoff produces one completion and one downstream release; stale edits cannot silently overwrite newer work |
| Audit and correction | Integration + staff rehearsal | Actions name the actual person and server time; correction preserves the original record and consistent downstream state |
| Team usability | Observed rehearsal | Each role can find its work and explain its next step, deadline and blocker without facilitator coaching after introduction |

For the shared test, target new assignments visible after refresh immediately and without refresh within five seconds. Treat this as a proposed acceptance target, not existing behavior. Capture case ID, sender, receiver, assignment, time, expected result, actual result and pass/fail for every handoff.
