Property Unit Tracker → hdpmchat Digital Board

Planning document — v1 draft, 7/22/2026

1. What the whiteboard actually is (reverse-engineering)

The board is a unit turnover pipeline tracker. Every row is one vacancy event moving through make-ready. Decoded:

Board element Meaning Digital equivalent
Row One unit currently in turnover TurnoverCycle record (a unit can have many over time)
Unit column Address/unit ID Link to Unit (AppFolio property/unit code, e.g. 42101, 42380)
Status magnet Green = on schedule, yellow = slight delay, red = behind, orange = major issue Computed health score — no more manual magnet moving
VAC Vacating tenant name + move-out date From notice-to-vacate (30-day notice)
RDY Target rent-ready date Editable target; drives all downstream scheduling
Columns A–M Make-ready phases: move-out inspect, contractors, cleaners, flooring, paint, punchlist… each cell = scheduled date + vendor + done mark Task records with type, vendor, scheduled window, status
Vendor magnets Wafford, C&E Cleaning, Sunrise, Carpet Smart, Firkus, 365 Contracting, Best Cleaners, OR Deschutes Paint… Vendor table
Margin notes (“Tri County no Fridays,” “Heavenly no Tuesdays,” “Tri County July 24–26”) Vendor availability rules & blackout dates VendorAvailabilityRule — weekly rules + date-range blackouts, enforced by the scheduler
Lockbox tag / # Lockbox assignment & code Field on the cycle; visible to authorized users only
ADVERTISED / PUNCHLIST tags Marketing + workflow flags Status flags on the cycle
Notes (“Move in 7/24,” “Selling,” “Owner!”) Move-in date, disposition notes Structured fields: moveInDate, disposition, free-text notes
Sticky note Miscellaneous to-dos Board-level task list / pinned note

Key insight: the status dot, the thing everyone glances at, is derivable. If today > a task’s scheduled date and it isn’t done, the row is behind. That alone removes the most error-prone manual step.

2. Automation model (the point of the exercise)

The lifecycle to automate end-to-end:

  1. Trigger — notice received. Tenant gives 30-day notice (already an HDPM process: “30 Day Ntc from Tenants Vacancy Tracking Form”). A turnover cycle is auto-created with unit, tenant, move-out date. No one “adds a row” anymore.
  2. Template expansion. A make-ready template (the A–M columns, encoded once) auto-generates the task list: Move-out inspection → contractor bids/repairs → flooring → paint → cleaning → carpets → punchlist → final walk. Each task type has a default duration and ordering.
  3. Auto-scheduling. Working backward from move-out date (or forward to hit the RDY target), the scheduler proposes dates for each task, honoring vendor weekly rules (“no Fridays”), blackout ranges, and simple capacity (a vendor isn’t double-booked across units the same day). Staff confirm/adjust — the system does the tetris.
  4. Status auto-computation. Green/yellow/red/orange from task states vs. today. “Behind” cascades: a late paint job pushes cleaning, which pushes RDY, which flags the move-in date at risk.
  5. Notifications in hdpmchat. It’s a chat app — so the board talks: daily digest (“3 units behind, 2 move-ins this week”), instant alerts (“822 SE Maui: flooring slipped, move-in 7/24 at risk”), vendor-day-before reminders, lockbox code on request.
  6. Close-out. Final walk done → cycle archived, unit flagged rent-ready, ADVERTISED workflow kicks in, move-in date confirmed.

Feeding it from AppFolio

hdpmchat already has AppFolio webhooks + read API access, so the board is event-driven from day one — no manual entry phase, no report-export workaround.

Event flow:

AppFolio signal Board reaction
Notice to vacate recorded (move-out date set on tenancy) Auto-create TurnoverCycle; expand make-ready template into tasks; propose schedule
Move-out date changed Reslide dependent tasks; alert if RDY/move-in now at risk
Work order created/updated/completed Sync to the matching Task (two-way reference via workorder_ref); completion advances the phase
Unit listed / marketing status Set/clear ADVERTISED flag
Lease signed on the unit Set moveInDate; lock the RDY deadline; countdown alerts
Tenant moved in Close and archive the cycle; snapshot metrics (days-to-ready, cost per turn)

The read API backs this up two ways: an initial backfill (current vacancies + open work orders → the board starts life matching reality, seeded against the whiteboard for validation) and a nightly reconciliation sweep that catches any webhook we missed, so the board can never silently drift from AppFolio — the failure mode that kills trust in a tool like this.

What stays app-side (not in AppFolio): vendor availability rules and blackouts, the scheduling engine, lockbox assignments, phase template definitions, status computation, and chat notifications. AppFolio is the system of record for facts (tenants, dates, work orders); hdpmchat owns the choreography.

One discovery task: enumerate exactly which webhook events our integration exposes and which read endpoints cover notices, work orders, and listings — the table above assumes the common set; the template expander keys off whatever the notice event actually carries.

AvailabilityRule vendor_id, weekly (e.g. no_friday), blackout_start, blackout_end
BoardNote      pinned board-level notes (the sticky note)
AuditLog       who changed what, when (whiteboards forget; apps shouldn't)

4. Views

  1. Board view (v1 default) — digital twin of the whiteboard: units as rows, phase columns, computed status dots, click a cell to edit a task. Familiar on day one; zero retraining.
  2. Calendar view — week/month; tasks as colored blocks, groupable by vendor (spot conflicts) or by unit (see one turnover’s arc). This is where “reverse-engineering it into a calendar” pays off.
  3. Unit drawer — click a row: full timeline, notes, lockbox, tenant history, linked work orders.
  4. Vendor view — one vendor’s week across all units; later becomes the vendor-facing portal.
  5. Mobile/read-only — field techs get today’s tasks + lockbox codes.
  6. TV mode — the wall-mounted replacement for the physical board: auto-refreshing board view on a monitor in the office. The whiteboard’s real virtue is ambient visibility; keep that.

5. Phased roadmap

Phase 0 — Discovery (days, not weeks). Enumerate available webhook events + read endpoints; confirm the A–M column semantics with the board’s owner (20-minute interview); encode the make-ready template. Backfill current vacancies via read API and validate the generated board against the physical whiteboard — that side-by-side is the acceptance test.

Phase 1 — Live digital board. Board view + unit drawer in hdpmchat, fed by webhooks (cycles auto-created from notices, tasks synced to work orders), computed status dots, audit log, TV mode on the office wall. Vendor/schedule edits are manual here — but the rows and facts are automatic from day one. Success = staff stop reaching for the markers.

Phase 2 — Choreography. Auto-scheduler with vendor availability rules and blackouts, nightly reconciliation sweep, chat digests and at-risk alerts, calendar view grouped by vendor or unit.

Phase 3 — Outside the office. Vendor confirmations (text/email “confirm Thursday?” → one tap), tech mobile view with lockbox codes, metrics (avg days-to-ready, vendor turnaround, cost per turn — data the whiteboard erases every week).
