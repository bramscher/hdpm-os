The API question, answered visually: the tool works either way — the cascade, the alerts, and the audit trail don't need AppFolio's permission. The write API only changes the third column: GUIDED (a human does it from a deep link, engine verifies) becomes AUTO (engine writes it, then verifies anyway). At ~$1/door/mo (~$850 for HDPM), the API pays for itself if it saves ~30 staff-minutes a day — but it's an upgrade, not a prerequisite. Ship guided-mode first, buy the API when the volume justifies it.

Group by vendor instead of unit and this same data becomes next month's capacity plan.

CONCEPT EThe daily driver — one person's everything, always prioritized. Every open item in the office has one owner and one next-action date, so priority is computed, not curated: overdue first, then things whose delay cascades, then today, then claimable, then watching. Nobody configures this page — it assembles itself from whatever carries your name. Switch desks to see the same engine build a different day:

How this differs from a Process Street / LeadSimple task list: those show your assigned tasks; the order is mostly yours to figure out. Here priority is computed from the data — overdue > cascade consequence (does delay move a tenant's move-in?) > due date > age — because every item is guaranteed to have one owner and one next-action date. Every card says why it's ranked where it is, every button is logged as your decision, and the same list becomes the Morning Card push at 7:42am. Knock out the top section and the day is won.
